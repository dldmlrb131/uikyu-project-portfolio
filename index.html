01

DaionSpace

실내를 직접 촬영해
길찾기 지도에 담았습니다.

복잡한 역과 건물에서 층과 시설을 확인하고 이동 경로를 찾는 실내지도입니다.

문제
같은 목적지라도 계단을 이용할 수 있는지에 따라 선택할 수 있는 길이 달라집니다. 낯선 실내의 사진과 지도에서 이 차이를 확인할 수 있어야 한다고 생각했습니다.
직접 한 일
비용을 고려해 어떤 공간 정보와 장비가 필요한지 조사했습니다. 360도 카메라를 구매해 실내를 직접 촬영하고 파노라마를 스마트맵에 적용했습니다.
구현
Claude와 작업한 저장소에는 얇은 벽과 좁은 통로의 경로 개선, 층간 길찾기, 계단 제외 옵션, 파노라마 방위 보정과 지도·거리뷰 연결이 기록돼 있습니다.

계단 제외와 대피 모드까지 구현됐으며, 실제 통행 가능 여부와 현장 안전성은 후속 검증 과제입니다.

02

Robot Atlas

로봇의 이동에 필요한
공간 데이터를 정리했습니다.

실내 영상·도면·센서 데이터가 좌표, 장애물, 이동 가능 정보로 이어지는 과정을 정리한 웹 로드맵입니다.

탐구 질문
파노라마에 담긴 장면만으로는 확인하기 어려운 거리, 위치, 장애물과 통행 조건을 어떻게 보완할지 조사했습니다.
직접 한 일
실내 이동과 현장 점검을 예시로 정하고, Codex와 영상·도면·센서 자료의 입력과 가공, 검증 단계를 비교해 웹에 정리했습니다.
검증
4m × 3m 합성 실내를 40 × 30 격자로 변환해 장애물, 관측된 빈 공간, 미관측 영역을 구분했습니다.
291개 화면 경로·탭

반응형 화면 33개와 함께 브라우저에서 확인

실제 주행과 현장 성능은 앞으로 확인할 범위입니다.

03

갤러리아트

작품을 둘러보고
내 공간에 배치해 봅니다.

온라인에서 작품을 탐색하고 방 사진에 배치해 작품의 크기와 위치를 가늠하는 전시 시제품입니다.

문제
SNS 작품 거래의 불확실성에서 출발해, 시제품에서는 작품을 자기 공간에 놓아볼 수 있는 흐름을 구체화했습니다.
직접 한 일
시제품을 사용하다 화면 전환과 작품 조작 중 끊김을 발견했습니다. Codex에 스크롤, 작품 이동과 확대 과정에서 원인을 찾도록 요청했습니다.
개선 결과
작품의 위치를 바꿀 때 관계없는 설명과 버튼 상태를 다시 쓰는 처리를 줄였습니다. 동일 브라우저 화면과 같은 드래그로 변경을 비교했습니다.
120회 → 8회

동일한 드래그 한 번의 화면 속성 변경 기록

시연 범위는 전시 탐색과 작품 배치입니다.

04

CookLoop

냉장고에서 조리까지
하나의 흐름으로 연결했습니다.

남은 재료를 확인하고 레시피, 식단, 장보기와 실제 조리까지 이어가는 웹 시제품입니다.

문제
메뉴를 골라도 보유 재료와 부족한 재료를 다시 확인하고 장보기 목록을 따로 작성해야 합니다.
직접 한 일
요리 발견부터 장보기와 조리까지의 흐름을 정했습니다. Codex에 웹과 향후 앱이 재고 계산 규칙을 공유하도록 개발 범위를 전달했습니다.
구현
조리 후 확인한 사용량을 재고에서 차감하고, 틀린 차감은 되돌릴 수 있습니다. 기존 기록 이관과 오프라인 재접속도 시험했습니다.
단위 테스트 12개 · 브라우저 테스트 12개

재고 계산, 차감·복원, 기존 기록 이관 등을 포함

사진 등록은 미리보기와 수동 입력을 지원합니다. 식재료 자동 인식, 영상 분석과 결제는 후속 계획입니다.

05

Live Safety Twin

도시 데이터와 실내 안내를
한 흐름에서 살펴봅니다.

세계에서 도시와 구역을 거쳐 실내까지 들어가 이동 경로와 공간안전 시나리오를 탐색하는 디지털트윈 시제품입니다.

프로젝트 주제
도시의 공간지도를 건물 내부 탐색과 연결해 층별 시설, 통로, 혼잡 상황을 한곳에서 확인합니다.
구현
공개 경계·도로·건물 데이터를 외부 지도에 표시합니다. 실내 데모에서 층간 경로, 장애 요소에 따른 우회와 인파 밀도 시나리오를 볼 수 있습니다.

외부 지도는 공개 공간 데이터를 사용합니다. 이 공개판에서는 예시 실내 모델로 층별 이동과 공간안전 시나리오를 살펴볼 수 있습니다.
